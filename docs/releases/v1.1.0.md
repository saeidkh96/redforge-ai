# RedForge AI v1.1.0

## Automated Repair Loop

v1.1.0 turns the existing Repair Agent contract into a bounded runtime loop.

When an applied generated patch fails repository-native tests, RedForge can now:

1. capture the failed test evidence,
2. request a minimal repair patch,
3. validate the repair with `git apply --check`,
4. apply the repair,
5. rerun repository-native tests,
6. repeat only up to the configured attempt limit,
7. persist every repair attempt in the `ForgeRun` record.

Repair is deliberately constrained. It runs only when patch application is enabled, an LLM provider exists, tests fail, and repair-on-failure is enabled.

## Configuration

- `REDFORGE_REPAIR_ON_FAILURE=true`
- `REDFORGE_MAX_REPAIR_ATTEMPTS=2`

The API can override these values per ForgeRun with `repair_on_failure` and `max_repair_attempts`.
