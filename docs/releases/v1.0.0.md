# RedForge AI v1.0.0

## Release scope

This release closes the initial roadmap from repository understanding through a human-gated pull-request integration layer.

### Milestones represented

- v0.1.0 — Repository Understanding
- v0.2.0 — Issue to Plan
- v0.3.0 — Plan to Code Patch

- v0.5.0 — Verification and Security

- v0.7.0 — Reliability foundations through deterministic verification boundaries
- v1.0.0 — End-to-end ForgeRun orchestration and persistence

## Verification philosophy

Generation is not verification. RedForge keeps LLM generation, deterministic execution, security checks, approval policy, and external PR actions as separate layers.

## Known limitations

- The generic LLM adapter assumes an OpenAI-compatible chat-completions endpoint.
- Patch quality depends on the configured provider; deterministic preflight only validates patch applicability, not intent correctness.
- Repair is exposed as an agent primitive but the default orchestrator does not automatically loop repairs without explicit policy.
- Security scanning is intentionally conservative and is not a replacement for Semgrep, Bandit, CodeQL, or organization-specific scanners.
- GitHub PR creation requires a caller-supplied token and is not triggered automatically by the default ForgeRun endpoint.
- Runtime sandboxing/container isolation is not implemented in core v1.0.0.
